# Synthetic data guarantees

**Every record in this repository is invented.** No real person, patient,
customer, bank account, vehicle, pupil or business appears anywhere in it.

This page sets out exactly what that means, how it is enforced, and — just
as importantly — the one place where the guarantee is weaker than you might
assume.

---

## What is invented

Everything that identifies anybody:

| | |
|---|---|
| **Names** | Generated by [Faker](https://faker.readthedocs.io/) from Spanish name lists. Common Spanish names recur, so a name here may coincide with a real person's — but it was never *taken* from anybody, and nothing else in the row relates to them. |
| **Addresses** | Real city and province names (public administrative geography), with invented street-and-number combinations. No address corresponds to a real dwelling or building. |
| **National identifiers** | Spanish DNI numbers with structurally valid check letters, generated at random. Registered to nobody. |
| **Bank accounts** | IBANs using the bank code `9999`, which the Bank of Spain has not allocated. |
| **Organisations** | Hospitals, supermarkets, schools, banks, insurers, car manufacturers and dealerships are all invented. Names follow real naming conventions so they read plausibly, but no existing institution is named. |
| **Products** | Grocery items, medicines and vehicle models are generic or invented. No trademark is used. |
| **Images** | Generated programmatically from the schema. Nothing is sourced, scraped or traced, so no copyright question arises. |

## What is real, and why that is fine

Some things in this data are genuine, deliberately. They are all **public
classification systems** — nomenclature, not information about people:

| System | Where | Why it is real |
|---|---|---|
| **ICD-10** diagnosis codes | `clinical/diagnoses` | WHO's public disease classification. Using the real codes is what lets you test a terminology lookup. |
| **LOINC** laboratory codes | `clinical/lab_results` | The international standard for identifying lab observations. |
| **ISO 18245** merchant category codes | `finance/merchants` | The scheme every card network uses to classify a business. |
| **Dewey / ISBN-13 / EAN-13** structures | `supermarket/products` | Public numbering standards. |
| **Spanish provinces and postal code ranges** | everywhere | Public administrative geography. |
| **Spanish cities** | everywhere | Real municipalities, so geocoding and mapping demos work. |

A diagnosis code is a fact about *a disease*, not about a person. Pairing a
real ICD-10 code with an invented patient produces synthetic data that is
still useful for integration testing.

Those systems have their own owners and their own terms, which this
repository's licence does not override. They are listed, with attributions,
in [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md).

## Contact details

These are the fields most likely to reach a real human by accident, so they
are handled deliberately.

### Email — provably unreachable ✅

Every address is on `example.com`, `example.org` or `example.net`. These are
reserved by [RFC 2606](https://www.rfc-editor.org/rfc/rfc2606) precisely so
that documentation and test data can use them. They are controlled by IANA
and do not accept mail.

Note the addresses go on the reserved domain *itself*, not a subdomain of
it: `pedidos.campo1@example.com`, never `pedidos@campo1.example.com`.

Enforced by `test_email_addresses_use_reserved_domains`.

### Telephone — valid, but not provably unreachable ⚠️

**This is the one guarantee that is weaker than the others, and it is worth
reading before you publish anything derived from this data.**

North America reserves `555-0100` to `555-0199` for fiction, so a US test
number provably cannot ring anybody. **Spain has no equivalent reservation.**

The numbers here are:

- randomly generated, never sampled from any real source
- structurally valid — nine digits, correct leading digit, province-matched
  dialling prefix — which is what makes them useful for testing a validator
- not linked to any real person, since every name and address is invented

But because they are structurally valid, a given number **could** in
principle belong to a real subscriber. That is an unavoidable trade-off: a
number that is provably unreachable is also one that fails validation, and
would make the data useless for the thing people most want to test.

If you need the absolute guarantee, set `RESERVED_PHONES = True` in
[`generators/common/geography.py`](../generators/common/geography.py) and
rebuild. You will get obviously-fake numbers that no validator accepts.

Enforced by `test_phone_numbers_are_valid_spanish_numbers` and
`test_landline_prefixes_match_their_province`.

### Payment cards — provably non-live ✅

Card numbers come only from the published test ranges every payment
processor recognises as non-live — the `4111 11…`, `5555 55…` and
`3782 82…` families. They pass the Luhn check, so they exercise the happy
path of a checkout form, and they can never move money.

Only the masked form and the last four digits are published. The full number
is never written to any file, which is also what PCI DSS requires of a real
system.

## How the guarantees are enforced

Not by review. By tests that run on every build:

```bash
python -m pytest -k "email or phone or postal"
```

| Test | Checks |
|---|---|
| `test_email_addresses_use_reserved_domains` | Every email is on a reserved domain |
| `test_phone_numbers_are_valid_spanish_numbers` | Nine digits, valid leading digit |
| `test_landline_prefixes_match_their_province` | Dialling prefix agrees with the address |
| `test_spanish_postal_codes_are_valid_and_match_their_province` | Codes are in the real 01–52 range |
| `test_emails_contain_no_accented_characters` | Accents transliterated, so addresses are usable |

## Reproducibility as verification

Every file is produced by the generators in this repository from a fixed
seed. Anyone can re-run the build and confirm they get back the files that
are committed, byte for byte:

```bash
python build.py --all
git status          # should report no changes
```

That is what turns "this data is synthetic" from a promise into something
you can check. The code that invented every value is right there, and if it
had been sourced from somewhere real, the rebuild would not reproduce it.

---

## If you find a problem

If any record in this repository resembles a real person, business or
account closely enough to concern you, please open an issue and it will be
regenerated. Because everything is generated from a seed, changing one value
means changing a constant and rebuilding — no manual editing, and no risk of
missing a copy in another format.
